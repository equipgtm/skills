# Facilitation recipe — deliver it, don't just produce it

Producing a workshop is half the job; running it live is the other half. This is the
train-the-trainer layer: the run-of-show, the timing, the cuts for the room, and what to do
when something breaks. Build it from the delivery brief in `PLAN.md` and the module set
so it stays in sync with the content. Write `facilitation.md`. For live events, include
the host/customer context, speakers and handoffs, helper roles, room/remote setup,
prework, breaks and the actual session agenda. Keep unresolved names visibly pending.

## Plan the cut

Use the supplied duration and agreed module scope. Select the depth that serves this
room and reserve time for setup, questions and a close. An optional hour-long example is
open (5m) → first build (15m) → main exercise (20m) → debrief (15m) → wrap (5m); adapt it
rather than replacing a requested 90-minute agenda. If all planned modules fit at full
depth, keep them; identify optional extensions only when time or audience needs call for it.

## Per-module run-of-show

For each module, note the full time, a **drop-to** (the shortest honest version) and a
**stretch-to** (the live, on-their-stack version). This lets you flex on the day.

## Read the room and tune

Match the cut to the audience the intake captured:

- **Experienced devs** — skeptical, hands-on. Go live on their repo; skip "what is an agent."
- **Analysts / non-deep-devs** — risk-first, less typing. Demo it, narrate it, keep code on
  screen.
- **Platform teams** — scale-minded. Lead with the at-scale or migration story, not toy edits.

Name a **win condition** per audience — the sentence you want someone to say, like "do that
on our repo."

## Pre-flight checklist

- Prereqs sent ahead (install, access, paid-plan notes)
- Content, exercise and feedback links tested for the cohort's frozen workshop version
- Access owner confirms accounts/projects/credits; learner preflight checks the required
  runtime and permissions; a fallback is ready for sign-in or access failures
- Setup/reset/cleanup helpers reviewed for the workshop's selected environment
- A scoped recovery move loaded (a pre-baked result) for when a live step wobbles
- One sentence of business value to open *and* close with

Keep instructor preparation and learner setup distinct. EquipGTM does not supply vendor
accounts or credentials. If learners use a coding agent, point them to the optional setup
prompt; notebook/console workflows need not require one. Introduce the application,
session route and architecture before the hands-on handoff. The workshop URL is typed
on a laptop (no QR); the close can show a survey QR with a readable URL fallback.

## After the session

Log what landed, which questions recurred, what objections came up, and whether anyone
asked to run it themselves. That feedback is the input to the refresh loop — it's how the
next delivery gets better.
